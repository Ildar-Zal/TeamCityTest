# TeamCity Test Automation Framework

Данный проект представляет собой фреймворк автоматизации тестирования для CI/CD платформы **TeamCity**. Основной упор сделан на проверку бизнес-логики через API, а также на валидацию ключевых пользовательских сценариев на уровне UI.

## Что тестируется (Тестовое покрытие)

Фреймворк покрывает основной сквозной пользовательский сценарий (**Main User Flow**):
* **Управление пользователями:** Создание и верификация учетных записей.
* **Конфигурация сборки:** Автоматическое создание проектов и билд-конфигураций (Build Configurations) через API.
* **Запуск пайплайнов:** Инициация и проверка прохождения сборки (Build Run).

>  **Архитектурный подход:** Вся основная бизнес-логика и генерация тестовых данных изолированы и тестируются на уровне **API**. Это обусловлено архитектурой самой платформы TeamCity, где вся ключевая логика (управление правами, конфигурация билдов, оркестрация) сосредоточена на бэкенде. Тестирование через API обеспечивает максимальную скорость и стабильность прохождения пайплайна. Уровень **UI** используется точечно и экономно — исключительно для проверки финального отображения интерфейса в браузере и валидации критических действий пользователя.


## Стек технологий

* **Язык:** Java
* **Тестовый движок:** JUnit 5 (использование современных аннотаций, параметризованных тестов и жизненного цикла)
* **Сборщик проектов:** Maven
* **Тестирование API:** REST Assured (взаимодействие со Swagger-спецификацией TeamCity)
* **Браузерная автоматизация:** Selenide / Selenium WebDriver
* **Инфраструктура:** Docker / Docker Compose / Selenoid
* **Отчетность и Уведомления:** Allure Report / GitHub Pages / Telegram API
  
## Архитектура CI/CD Пайплайна

В проекте настроен полноценный автоматизированный цикл непрерывной интеграции (локальный ручной запуск не требуется). При каждом `Push` или `Workflow Dispatch` пайплайн выполняет следующие шаги:

1. **Кэширование окружения:** Для ускорения сборки применяется кэширование Maven-зависимостей (`~/.m2/repository`) и предварительный пуллинг стабильных образов браузеров для Selenoid.
2. **Развертывание стенда (Idempotency):** Через кастомный Composite Action поднимается контейнер `Postgres`. Из защищенного хранилища (через GitHub Secrets) скачивается слепок настроенной системы (`tc-backup.zip`). Утилита `maintainDB.sh` разворачивает бэкап, решая проблему «холодного старта» сервера.
3. **Безопасность:** Пайплайн динамически парсит логи `teamcity-server`, извлекает временный `Super user authentication token` и прокидывает его в переменные окружения (`TEAMCITY_AUTH_TOKEN`) для REST Assured. Боевые секреты в кодовой базе отсутствуют.
4. **Тестирование:** Тесты запускаются в многопоточном режиме. UI-тесты маршрутизируются на локальный хаб Selenoid (`http://localhost:4444/wd/hub`).
5. **Анализ покрытия API:** Утилита `swagger-coverage` сопоставляет прошедшие API-запросы со Swagger-схемой и генерирует детальный HTML-отчет о покрытии эндпоинтов.
6. **Сборка отчетности:** Пайплайн скачивает историю прошлых запусков из ветки `gh-pages`, агрегирует новые результаты Allure и Swagger Coverage, формирует статический сайт и публикует его на **GitHub Pages**.
7. **Уведомления:** По завершении (даже в случае падения тестов) срабатывает Telegram-бот, отправляющий в чат краткий статус сборки, автора коммита и прямые ссылки на опубликованные Allure-отчет и Swagger-метрики.

---
*Примечание: В целях безопасности инфраструктурные секреты (токены Telegram, URL бэкапов) изолированы в GitHub Secrets и не опубликованы в открытом доступе. Репозиторий предназначен для демонстрации навыков построения комплексной тестовой архитектуры и DevOps-практик в QA.*
